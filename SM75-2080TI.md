# sm75-2080Ti branch

Strata `main` (99f3dbd) plus four upstream pull requests, as run in production on
2x RTX 2080 Ti 22 GB (Turing, sm_75, NVLink pair) with Qwen3.8-Flash-Next IQ3_S.

#646, #655, #652, #716 and #742 were merged without edits. #743 conflicts with #646 in `qsa_block_topk`
(`src/kernels/cuda/qsa_select.cu`): both change the condition that falls back to the reference top-k. The resolution keeps
#743's streaming branch first and then #646's `(capacity_guard && reach > fit)` fallback, so both behaviours are kept.
The source tree (everything except this file) is byte-identical to the one the production engine was built from.

## Build

```
  -DCMAKE_CUDA_ARCHITECTURES=75 -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCUDAToolkit_ROOT=/usr/local/cuda-12.8
cmake --build build --target strata
```

## Turing decode-kernel work (SM75-2080TI branch only, 2026-10-04)

Two changes to `iq_kernels.cu`, each bitwise-identical to the stock kernel (the repo's own parity suite
proves it: every IQ3_XXS / IQ3_S weight type crossed with every down type, including the model shapes
2560x640 and 2560x768) and each keeping a runtime off-switch.

**1. IQ3_XXS / IQ3_S codebooks staged in shared memory** (`STRATA_IQ_STAGE_GRID=0` to disable).
The decode-once (`Split`) kernels read the 256x u32 (IQ3_XXS) and 512x u32 (IQ3_S) grid tables from
global memory on every k-step; IQ2_S and the other staged types already copied theirs to shared memory.
Staging them cuts `lg_throttle` (the load/store unit's queue-full stall) from 19.5 to 11.9 per issue and
takes the gate/up kernel from 221.6 to 187.6 us (-15%), the whole layer call from ~350 to ~314 us (-10%).

**2. Activations staged in shared memory per block** (`STRATA_GU_STAGE_X=0` to disable).
`native_gu_multi_kernel` runs 8 warps (8 rows) per block and every warp re-read the same 4-token
activation chunk from global memory, ~9 loads per token per k-step. The block now copies the chunk to
shared memory once (`__syncthreads` before and after) and all 8 rows read it there. The gate/up kernel
falls to 161.1 us (305 GB/s, `lg_throttle` gone, the top stall is now `long_scoreboard` 4.5). The kernel
is only used when `n_embd / 32 <= 80` (n_embd <= 2560); otherwise the per-warp global path is kept.

Kernel-level, 48 calls in one graph, model shapes, interleaved rounds: stock 348-352 us per layer call,
+1: 313-315 us (-10%), +1+2: 291-293 us (-16%). End-to-end, same-window A/B, mining stopped, 10 graded
temp-0 questions md5-identical in every arm and 60K-token prefill unchanged:

| arm | decode pooled (tok/s) | ms/verify window |
|---|---|---|
| production (before) | 79.21 (79.16 / 79.27) | 35.87 / 36.14 |
| +1 | 80.26 (80.27 / 80.25) | 35.45 / 35.74 |
| +1+2 (measured against the +1 build) | 81.41 (81.45 / 81.36) | 34.81 / 34.98 |

Both are promoted on this box: `+1+2` is production since 2026-10-04 22:55:28 (tag `prod-k2-20261004`,
rollback `~/strata/rollback_strata_k2.sh`). The end-to-end gain is small because the gate/up kernel is
about two thirds of the routed-expert time, which is about 31% of one GPU stage, and a single request
still walks the two cards serially.
