# sm75-2080Ti branch

Strata `main` (99f3dbd) plus four upstream pull requests, as run in production on
2x RTX 2080 Ti 22 GB (Turing, sm_75, NVLink pair) with Qwen3.8-Flash-Next IQ3_S.

## What is merged

| Upstream PR | Head | What it does |
|---|---|---|
| [#646](https://github.com/Niko1221/Strata/pull/646) | ee5a0bf | decode kernels: sub-warp expert packing, shared-memory staging, batched PLE/MTP, 1,024-thread top-k |
| [#655](https://github.com/Niko1221/Strata/pull/655) | 7b2dcd3 | sm_7x: prompt-path BF16 products on the FP16 tensor cores (`STRATA_BF16_TC=0` turns it off) |
| [#652](https://github.com/Niko1221/Strata/pull/652) | cf14881 | serve: commit only the tokens a verify window hands out (multi-turn resume) |
| [#716](https://github.com/Niko1221/Strata/pull/716) | 0de9867 | conversation parking with `--layer-split` |
| [#742](https://github.com/Niko1221/Strata/pull/742) | 309e954 | QSA selection: FP32 tiled block scorer below sm_80 (`STRATA_SELECT_SIMT=0` turns it off) |
| [#743](https://github.com/Niko1221/Strata/pull/743) | 83cf4dd | QSA selection: coalesced streaming top-k for long Turing prompts (`STRATA_TOPK_STREAM=0` turns it off) |

#646, #655, #652, #716 and #742 were merged without edits. #743 conflicts with #646 in `qsa_block_topk`
(`src/kernels/cuda/qsa_select.cu`): both change the condition that falls back to the reference top-k. The resolution keeps
#743's streaming branch first and then #646's `(capacity_guard && reach > fit)` fallback, so both behaviours are kept.
The source tree (everything except this file) is byte-identical to the one the production engine was built from.

## Build

```
cmake -G Ninja -S . -B build -DCMAKE_BUILD_TYPE=Release -DSTRATA_ENABLE_CUDA=ON \
  -DCMAKE_CUDA_ARCHITECTURES=75 -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCUDAToolkit_ROOT=/usr/local/cuda-12.8
cmake --build build --target strata
```

## Production engine arguments (relevant part)

```
--expert-cache auto --prefill auto --spec 4 --spec-min-p 0.5 --mtp <rt>
--max-context 262144 --kv int8 --kv-resident 32768 --vision --vram-reserve-mib 700
--layer-split auto   (two GPUs, NVLink pair)
--conversation-cache-mib 8192 --conversation-cache-slots 4
```

## Measured on this box (same-window A/B, 2026-10-04)

Hardware: EPYC 7K62, 128 GB RAM, 2x RTX 2080 Ti 22 GB (NV2), CUDA 12.8.

#716 with `--conversation-cache-mib 8192`: two ~32K-token conversations alternating over 7 turns.
Every switch read 32K tokens again without it (TTFT 17.0-17.9 s); with it the switch restored the
parked conversation (32,043-32,134 tokens reused, TTFT 0.49-0.64 s). All answers were md5-identical
to the baseline. The upstream parity gate `tools/conversation_cache_parity.py` passed `reuse` (spec 1,
byte-exact main-model state), `reuse` (spec 4) and `pressure` (byte-exact) on the layer split.

#742 + #743, cold prompts with a unique nonce each (no prefix reuse), same-window A/B base / both / #742 only / both / base:

| prompt | before (2 runs) | #742 + #743 (2 runs) | #742 only |
|---|---|---|---|
| ~31K tokens | 1845 / 1842 tok/s | 1899 / 1895 | 1890 |
| ~130K tokens | 1943 / 1952 | 2307 / 2308 | 2325 |
| ~252K tokens | 1539 / 1535 | 2280 / 2293 | 2022 |
| ~252K time to first token | 163.5 / 164.0 s | 104.9 / 109.8 s | 124.5 s |

`qsa select` at 252K (`STRATA_PREFILL_TIMING=1`): 61.4 s (40% of the GPU timeline) -> 23.5 s (#742) -> 8.1 s (both).
Ten exact-answer temp-0 questions gave identical output (md5) in all five arms; every needle was found.

#741 (BF16 prompt GEMMs on the FP16 tensor cores) was not merged: #655 already covers that path and the two conflict.

Tested and not merged on this box: `--peer-device` (decode +6%, prompt reading -33..-39%), #639 + #583 + #732
(within noise at a 97.5% expert-cache hit rate).
