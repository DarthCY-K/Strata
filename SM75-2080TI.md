# Turing (sm_75) branch — RTX 2080 Ti 22 GB ×2

This branch is the Turing-specific line of Strata. It is based on upstream **v0.1.39** (`6f32ec0`) and carries
the upstream pull requests and the local patches that this box runs in production; it replaces the earlier
0.1.38-based line of this branch.

Test box: EPYC 7K62, 128 GB RAM, 2× RTX 2080 Ti 22 GB (sm_75, NV2 island pair), CUDA 12.8, Qwen3.8-Flash-Next
IQ3_S (2560×640 experts), layer split 24/24, int8 KV, `--conversation-cache-mib 8192 --conversation-cache-slots 4`.

## What is in this branch, on top of v0.1.39

| Item | Kind | Note |
|---|---|---|
| **PR #783** fused decode/verify/MTP kernels + graph-launch reductions | upstream PR, taken as-is | its 32 files were taken from the PR head; merges cleanly on 0.1.39 |
| **PR #742** FP32 tiled QSA block scorer below sm_80 | upstream PR | long-prompt prefill on Turing |
| **PR #743** coalesced streaming top-k for long Turing prompts | upstream PR | re-resolved against 0.1.39: the stream branch must sit *before* the `too_small` / `kWideMinBlocks` decision, not inside its body |
| **PR #731** no duplicate expert slots across helper and primary GPUs | upstream PR | inert here (no helper devices), carried for completeness |
| **PR #764** `STRATA_ADAPT_LAG` — #463's reproducibility without its stall | upstream PR | |
| **k1** IQ3_XXS / IQ3_S codebooks staged in shared memory | local | the decode-once kernels read their 256/512-word grid tables from shared memory as IQ2_S already did; `STRATA_IQ_STAGE_GRID=0` off |
| **k2b** the gate/up block stages its activation chunk in shared memory | local | covers both of #783's paths (the 16-lane sub16 path used at n_embd 2560 and the warp path); `STRATA_GU_STAGE_X=0` off |
| **sm_75 BF16 GEMM path** | local fix | 0.1.39's `bf16_path()` ends with `return cc < 75 ? 1 : 0;`, i.e. sm_75 is sent to cuBLAS while sm_70/72 get the FP16 tensor-core path. On this box that doubles the hyper-connection stage of prefill. The branch returns `cc < 80 ? 1 : 0` so sm_75 keeps the tensor-core path; `STRATA_BF16_TC=0` still forces cuBLAS |

All of these are bitwise-identical to what they replace, and the repo's own parity suite proves it on this card:
`native_grouped_parity` (57 "bitwise equal" comparisons, 0 failures), `mmvq_multi_parity`, `iq_multi_parity`,
`gemm_bf16_parity` and `bf16_gemv_parity` all report 0 failures.

## Measured (2026-10-05, same-window A/B, mining stopped)

| | 0.1.38 line (previous production) | this branch |
|---|---|---|
| decode, 6 prompts pooled (tok/s) | 81.34 (81.47 / 81.21) | **84.91 (84.55 / 85.29)** |
| 60K-token prompt read (tok/s) | 2171 | **2178 / 2180** |
| 32K / 130K / 252K prompt read (tok/s) | 1930 / 2342 / 2297 | 1900 / 2332 / **2304** |
| ms per verify window | 34.6-34.9 | **33.8-34.1** |
| decode kernel bench, 48 layer calls | 288.5 / 290.7 µs | **262.8 / 264.5 µs** |

Temperature-0 graded answers are md5-identical between the two lines (10/10 questions), and every needle in the
long-context prompts was found. Tool calls (`get_weather` with a Chinese city) and the vision path (a generated
pure-red image answered "红色") work on the served endpoint.

Not adopted on this box, with the measurement that rejected it: **PR #761** (a prefill stage no longer waits for
the whole split below it) — 32K 1949→1884, 130K 2371→2338, 252K 2309→2304 tok/s. A 2-stage split has no bubble to
fill: the prefill GPU timeline is already 98% of the wall time. It needs ≥3 stages.
